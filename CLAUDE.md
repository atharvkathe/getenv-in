# CLAUDE.md: getenv.in

Technical notes for this repo. For product direction read `PRODUCT.md`, and for the planned visual redesign read `DESIGN.md`.
(The parent folder's `CLAUDE.md` describes a "WAT" layout with `tools/` and `workflows/`. This repo has neither.)

## Tech stack

- **Static site, vanilla JS, no build system.** There is no `package.json`, no bundler, no framework, no TypeScript and no npm dependencies.
- Plain `<script>` tags (not ES modules). Every file shares one global scope.
- Plain CSS: `styles.css` and `animations.css`, with custom properties on `:root`. Tailwind is **not** used. The word "Tailwind" only appears as a stack option in data and UI text.
- External resources loaded in `index.html`: Google Fonts (JetBrains Mono), Mermaid 10.5.0 from jsDelivr, Google Analytics (gtag) and Google AdSense.
- Node.js (only `fs`/`path`) is used solely for the one-off generator and patch scripts.
- Hosted on Vercel. `vercel.json` only sets security headers.

Script load order (end of `index.html`) matters because everything is global:
`data-generators → data-templates → models → utils → storage → renderers → knowledge-engine → blueprint-engine → workspace → stack-data → presets-core → compiler-core → seo-content-db → app → animations`.
`compiler-core.js` builds `elements` with `getElementById` as soon as it loads, so it must load after the markup.

## Run / build / test (Windows)

There is no dev server, build step, test suite or linter. To run it, serve the repo root with any static server:

```powershell
npx serve .                     # or:
python -m http.server 8000      # then open http://localhost:8000
```

Don't open `index.html` via `file://`. Assets use absolute paths (`/styles.css`) and routing uses `history.pushState`. On a plain static server (and on Vercel, which has no rewrites in `vercel.json`), a hard refresh on SPA-only paths like `/workspace` or `/templates/x` returns 404. Only `/` and the pre-rendered `blog/*` and `stack/*` paths exist as files.

Regenerate content (run from the repo root):

```powershell
node build-blog-pages.js     # rewrites blog/*/index.html from index.html
node build-stack-pages.js    # rewrites stack/*/index.html from index.html
node generate-stacks.js      # rewrites stack-data.js (see the bug below)
```

The only way to check the code is a syntax pass, for example `node --check app.js`.

## How the .env generator works

Everything lives in `compiler-core.js` unless noted otherwise.

1. **Step 1:** `renderFrameworkGrid()` → `selectFramework(id)`. Each `FRAMEWORKS` entry has a `prefixType` (`nextjs`, `vite`, `astro`, `flutter` or `none`).
2. **Step 2:** `renderServicesGrouped()` → `toggleService(id)` adds IDs from `SERVICES` to `state.services` (a `Set`). `handleServiceSearch` filters the list and `evaluateWarnings()` shows stack warnings.
3. **Step 3:** `compileDotenv()` builds the file line by line:
   - general vars come from `getFrameworkGeneralVars(framework, activeEnv)`, then each service's vars from `getServiceVariables(id, framework, activeEnv, envConfig)`;
   - vars with `type: 'public'` get a framework prefix: `NEXT_PUBLIC_`, `VITE_` or `PUBLIC_`;
   - `ENV_VALUES[activeEnv]` (development, staging or production) supplies `DATABASE_URL`/`REDIS_URL` and a header comment;
   - `state.activeTab === 'example'` empties every value to produce `.env.example`;
   - secrets come from `state.generatedSecrets[env]`, filled by `generateSecureSecret()` in `app.js` (`crypto.getRandomValues`, 32 bytes as hex), and `isSecretVariable()` decides which vars count as secrets;
   - the output goes to `renderSyntaxHighlightedCode()`, and the raw text is stored in the `data-raw` attribute of the copy and download buttons.
4. Presets: `applyPreset()` in `app.js` and `compilePresetDotenv()` work from `PRESETS_DATA`.
5. Persistence:
   - `localStorage`: `env_last_framework` and `env_last_services` (the "remember last stack" banner) and `getenv_workspace` (the workspace);
   - `sessionStorage`: `env_session_*` and `env_boot_completed`;
   - share links: `handleUrlImport()` and `generateShareLink()`.
6. Pre-rendered stack pages set `window.PRELOADED_STATE = { framework, services }`, and `init()` uses it to jump straight to step 3.

## Routing

`handlePathRoute()` in `app.js` removes `active-view` from every view and then matches `location.pathname`:
`/`, `/about`, `/privacy`, `/resources` and `/blog`, `/generators`, `/architect`, `/workspace`, `/search`, `/templates`, `/templates/:slug`, `/stacks/:slug`, `/integrations/:slug`, `/blueprints/:slug`, `/pricing`, `/stack/:slug` and `/blog/:slug`.
Unknown paths fall through to the home view.
In `init()`, a global click handler intercepts every `<a href="/...">` and runs `pushState` + `handlePathRoute()`. Many generated links also do this inline through `onclick`.
Note that `/stacks/:slug` (from `SEO_STACKS`) and `/stack/:slug` (from `STACK_PAGES`) are different routes with different data.

## Styling

- `styles.css` uses tokens on `:root`, including `--bg-base`, `--bg-surface`, `--border-muted`, `--accent-color` (`#22c55e`, green), `--text-primary/secondary/muted` and `--syntax-*`.
- The site is dark only, set in JetBrains Mono.
- Heavy inline `style="..."` in `index.html` and in JS template strings.
- `DESIGN.md` describes a **different, not yet implemented** theme (saffron `#FF8A1F`, Space Grotesk/IBM Plex). Today's CSS does not match it.
- `styles.css` contains a "CODE PROTECTION STYLES" block added by `update-css.js`.

## Shared code / "components"

There is no component system. Markup lives in `index.html`, or comes from JS functions that return template-literal HTML and set it with `innerHTML`, for example `renderTemplatesGrid` and `renderSEOHubPage` in `app.js`, and `Renderers.*`.
Shared helpers: `Utils` (`utils.js`), `Models.create*` (`models.js`), `showToastNotification()` (`app.js`).

## Conventions

- 2-space indent and single quotes.
- Sections are marked with `/* ===== SECTION ===== */` banners. Comments label features as "FEATURE N".
- Older code uses global functions plus `state` and `elements`. Newer files use object-literal namespaces (`const X = { method() {} }`).
- Optional calls are guarded with `typeof fn === 'function'`, and optional DOM nodes with `if (elements.x)`.
- Data is kept as large JS arrays and objects in `*-db.js`, `*-data.js` and `data-*.js` files.

## Fragile / confusing: read before editing

1. **`app.js` currently throws at load.** Both `storage.js:7` and `app.js:1358` declare `let workspaceState` in the shared global scope, so the browser raises `SyntaxError: Identifier 'workspaceState' has already been declared` and none of `app.js` runs (`init()` included). `app.js` still contains the old workspace functions (`initWorkspace`, `saveWorkspaceState`, and others) that `storage.js` and `workspace.js` were meant to replace. `WorkspaceController.bindEvents()` is never called.
2. **`stack-data.js` is a syntax error.** `generate-stacks.js:63` writes a literal `\n`, so `const STACK_PAGES = [` ends up inside the first-line comment. `STACK_PAGES` is therefore undefined, and `/stack/:slug` redirects to `/`. Re-running the generator reproduces the bug.
3. **`generate-knowledge.js` doesn't parse** (`node --check` fails), and it writes to a hard-coded absolute Windows path.
4. **`compileDotenv` is defined twice** in `compiler-core.js` (lines 2589 and 3460). The second definition wins, so editing the first changes nothing.
5. **`handleGenerate()` is called in `init()`** (in the `PRELOADED_STATE` branch) but is never defined, so pre-rendered stack pages hit a ReferenceError there.
6. **Pre-rendered pages are stale snapshots of `index.html`.** They reference `/validator-core.js` (which doesn't exist) and a relative `animations.css` (which 404s under `/blog/x/`), and they don't include the newer scripts. The build scripts only rewrite paths for a fixed list of files, so relative `src="models.js"` and similar paths would also break. Their exact-string injection targets no longer match `index.html`: `build-stack-pages.js` looks for a `<!-- How It Works View -->` comment, and the `blog-post-view` block in `build-blog-pages.js` now has extra blank lines. When a target doesn't match, the content is not injected. The stack script prints a warning, and the blog script fails silently.
7. **Duplicated data must be kept in sync by hand.** `BLOG_POSTS` exists in both `compiler-core.js` and `build-blog-pages.js`, and `update-blogs.js` contains a third copy. The stack slugs in `build-stack-pages.js` (for example `nextjs-supabase-stripe`) differ from those in `generate-stacks.js`/`stack-data.js` (for example `nextjs-stripe-supabase`).
8. **The CSP in `vercel.json` is `script-src 'self' 'unsafe-inline'`.** That blocks the gtag, AdSense and jsDelivr (Mermaid) scripts that `index.html` loads.
9. **`update-*.js` scripts do blind string replacements** on source files. Don't re-run them without reading them first.
10. `elements.howItWorksView` and `elements.blogView` are referenced but never defined. The guards make them no-ops.
11. Git shows LF→CRLF warnings. The build scripts handle both line endings only for some match targets.
